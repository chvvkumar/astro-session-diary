AstroLog UI — Full Design Summary

Review all decisions before we write the spec

Philosophy

Full replacement of the current gallery-centric frontend with a data-first target aggregation dashboard. Thumbnails are de-emphasized — only shown in the detail drawer. The UI is an automated logbook for querying imaging sessions by target, equipment, filters, and arbitrary FITS metadata.

Key Decisions

LAYOUT
Sidebar Filter + Feed
Persistent left sidebar, scrollable target feed
FILTER BARS
Colored Pill Badges
Ha·13.6h style, per optical filter
SESSIONS
Query-time groupings
GROUP BY date+target, filtered dynamically
API STRATEGY
Evolve existing endpoints
Extend /api/targets and add session detail
QUALITY METRICS
Dedicated columns
median_hfr, eccentricity on images table
REACTIVITY
Immediate filter application
No "Apply" button, FITS query on Enter
ROUTING
@solidjs/router
/ (dashboard) and /admin (stats)
SCAN + STATS
Dedicated /admin page
Dashboard grid with full analytics

Backend Changes

Migration: Add median_hfr, eccentricity, telescope, camera columns to images table
GET /api/targets: Full aggregation endpoint with all filter params → targets + nested sessions + aggregates
GET /api/targets/{id}/sessions/{date}: Heavy detail for drawer (thumbnail, quality metrics, raw headers)
GET /api/targets/equipment: Distinct cameras + telescopes for dropdown population
GET /api/stats: New endpoint for admin page analytics (equipment inventory, filter usage, timeline, quality distributions, storage, ingest history)
Ingest pipeline: Extract telescope (TELESCOP), camera (INSTRUME), HFR, eccentricity from FITS headers during ingest
